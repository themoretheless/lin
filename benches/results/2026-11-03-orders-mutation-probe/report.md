# Isolated orders mutation/first-SUM harness: prepared

examples/orders_probe.rs is a standalone example, not a production runtime change. It complements completed whole-process lifecycle run 41651338091, which cannot isolate individual writes or initial aggregate cache cost.

Each fresh Db has one user; prepared orders statements contain at most 500 records. INSERT timing includes memory transaction creation, running all prepared statements and commit. Preparation/source-string construction stays outside the operation timer. Immediately after INSERT, measure first SUM without preflight execution, then one repeat SUM. Next perform a one-row CAS UPDATE o-0 total=201, first SUM after invalidation, one-row CAS DELETE of the last row, and first SUM after invalidation. Every affected count, scalar total and every id/user_id/total at all three states is checked outside the timers; complete states are returned for independent audit. No embeddings/FTS/index/sync behavior is disabled. Orders schema follows its normal default behavior; the harness does not create docs or assert orders have automatic embeddings.

Local release harness test passed for row counts 2/499/500/501/1000 and invalid empty/sample inputs. This checks statement/chunk boundaries, output states and sum invalidation. No new performance evidence is claimed. Planned independent frozen comparison uses exactly the same example bytes against correct baseline a28aa758b and current f37-equivalent runtime, with both exact ordinary release binaries preserved. First SUM is cold with respect to the aggregate summary, not guaranteed cold CPU/page cache. Full state checks between phases affect cache state equally; mutable-query preparation and arbitrary write contracts are not measured. No peer victory or full objective completion follows from this harness alone.
