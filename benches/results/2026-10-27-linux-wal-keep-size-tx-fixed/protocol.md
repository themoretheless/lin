# Bounded Linux KEEP_SIZE WAL reservation: functional qualification first

Baseline Rust content:production04749994. Candidate changes only persist.rs and preserves exact public Row/API. No WAL codec/payload,sync mode,CRC,replay/rollback,index/FTS/embedding or quota guard is changed. New private Linux helper uses the pinned libc0.2.189 fallocate(FALLOC_FL_KEEP_SIZE),best-effort;unsupported/error results retain ordinary write/sync behavior. Checked offset/length conversions avoid truncation on narrower off_t.

Reservation geometry starts at actual logical EOF,not offset zero or total historical sparse length. The length is the next1MiB multiple of additional bytes,less than additional+1MiB. Additional hints are capped at MAX_RECORD+13 (16MiB envelope-sized bound);zero,overflow,out-of-off_t/64-bit end or already allocated requests are skipped. Filesystem allocation granularity may add physical blocks;all EOF,cursor and contents must remain unchanged. A separate u128 oracle checks1056 boundary combinations,including sparse large offsets and maximum integer inputs.

Placement matters. A real Linux ARM64/overlayfs probe showed ftruncate(0) discards1MiB of reserved space even when logical EOF was already zero. Thus the Linux candidate skips the initial open_log hint (Store::open subsequently replays/truncates) and refills at actual small Full frame writes,plus the existing >=64KiB frame path. No hint is inserted into truncate/close. Empty databases and successfully closed/checkpointed logs should not retain an idle reservation;first-write reservation work occurs inside write execution. Relaxed small frames gain no metadata syscall. Large relaxed frames inherit the existing large-frame reservation placement. All of these cold/setup,Full/Normal and disk-space effects require performance/resource controls;no speedup is inferred here.
