# Point values: одинаковый результат и проверка контракта

Добавлен отдельный `point_values` benchmark для Lin, SQLite и DuckDB: hit/miss по primary key в 10 000 строках. Все три движка полностью читают `id/title` и возвращают `Vec<(String, String)>`. Чтение, преобразование в owned String и уничтожение результата входят в измерение; создание и уничтожение входной БД исключены. Ожидаемые строки построены независимо от результата запроса. Сравниваются байты обеих строк и кратность результата.

Локальная проверка macOS ARM64: 6/6 сценариев `bench_checked` завершены, 6 наблюдений; отдельный oracle проверил 6 фактических результатов и 5 намеренно неверных наборов. Три независимо собранных runtime-mutant варианта (Lin, SQLite, DuckDB) возвращают id вместо title; каждый отвергнут валидатором с exit 1. Положительный исходник восстановлен после подмен. Это функциональный smoke, не квалификация latency и не доказательство превосходства над peer.

## Ограничение исторического point_get

Статический аудит закреплённого compare.rs подтвердил: Lin материализует id/title, но наружу возвращается done.n; SQLite/DuckDB/PostgreSQL/MySQL выполняют COUNT(*), HashMap возвращает длину title. Исторический point_get не использует full-value bench_checked. Успешные read smoke-прогоны этого сценария не доказывают правильность возвращённых id/title. Bulk-проверки имеют отдельные валидаторы; ограничение нельзя переносить на все сценарии или отдельный Python peer-refresh.

Старые результаты и знаменатели сохранены. Их point_get отношения отражают указанные разные контракты, а не скорость одинакового возвращаемого результата. Сравнение двух версий Lin в одном неизменном сценарии остаётся измерением того же сценария. Новый point_values дополняет историю и не заменяет невыгодные наблюдения.

Новая семья пока покрывает только Lin/SQLite/DuckDB. Для PostgreSQL, MySQL, MongoDB, pandas, MSSQL и Kusto эквивалентный сценарий здесь не реализован. Полная цель восьми движков остаётся открытой. Исходники runtime не менялись; COW разрешён для следующей версии API, но его принятие требует прохождения полной квалификации.

Сырые положительные/отрицательные результаты, исходники mutant, журналы компиляции и provenance сохранены рядом. `sha256.json` содержит контрольные суммы всех файлов пакета, кроме самого manifest.
