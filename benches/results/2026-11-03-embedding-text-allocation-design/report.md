# Next embedding hypothesis: reuse text assembly storage

Current runtime equals frozen b9f10bc776b05eb5235237e9a900c2ef6aaed1fd after rejecting the64-word token-slot cache. Existing evidence rules out unchanged retries of alphabetic trigram lookup (2026-10-04-embed-trigram-table: native1k -3.53%,10k -4.38%), token feature caches, constant-modulo specialization, owned thread pools and caller-participation variants.

Source inspection: maybe_embed_rows creates a Vec<Cow<str>>; each row with multiple embedding fields allocates a combined String through row_embed_text before batch embedding. The hashing implementation subsequently uses per-thread scratch for case conversion, but the combined text allocation remains one per row. Linux phase evidence measures text assembly separately around1.5ms per10k at100k; that is an opportunity boundary, not a promised whole-operation gain. Changing allocation placement may also affect later vectors, but that is unproven.

Next concrete candidate should pass field parts to the default hashing implementation and reuse one joined-text buffer per serial worker. It must preserve title/body/snippet order, omit missing fields, suppress separators before the first nonempty field, preserve separators for present empty trailing fields and skip rows whose complete text is empty. Existing explicit vectors remain untouched. Default third-party behavior must continue to receive the exact same assembled text sequence through embed_batch, including the existing fallback to individual embed calls for incorrect batch length. No unsafe borrowing across thread lifetimes, no cloned owned strings transferred to persistent queues, no vector/model/dimension changes.

A new default trait method would be additive but its contract must be documented and tested before use. The HashingEmbedder override can use scoped workers with the same scheduling thresholds and output order, collecting vectors while reusing text storage inside each worker; whole-string bigrams still include precisely the original spaces. Validate reference f32 bits across empty/missing/Unicode/whitespace fields, explicit vectors, custom/broken batch embedders and dimensions; then workspace and fresh source/lifecycle/RSS, FULL WAL and peer gates. Keep timing assembly inside INSERT. The default read path and public Row remain unchanged.

No new runtime implementation or performance measurement is claimed by this design audit. Full eight-peer objective remains unfinished; all rejected candidate data remain preserved.
