# Diagnostic protocol: Normal-mode checkpoint concentration

Baseline-only diagnostic; no optimization candidate and no production source edits. Build a temporary owned Rust example, save the resolved compiler-artifact executable, then remove the example. Pin every core source, Cargo inputs, probe and executable by hash. Three fresh processes for each engine rotate order across repetitions.

Each process performs1000 growing transactions with five inserts each, matching the old tests/tx_bench.rs Normal-mode business fields. Lin dynamic parse/run and SQLite execute parsing remain inside each transaction timer. SQLite WAL synchronous=NORMAL and default1000-page autocheckpoint are asserted; Lin Normal and the existing32-commit checkpoint threshold are unchanged. Per-transaction clocks are added; Lin writes_since_snapshot counter reads are outside the timer. Buffer all1000 sample records and emit JSON only after the loop and full independent input-value readback after ordinary close/reopen. Drop handles before cleanup; temporary directories are uniquely owned. Final close/sync lies outside operation timers, matching the old scope. This is not a power-loss claim.

Checkpoint-labelled transactions are observed by the real counter reset after successful commit; assert the full modulo32 sequence starting with the seed write. Every process must produce exactly1000 indexed positive observations. Lin has31 checkpoints and969 ordinary transactions. Analyze sum of full-transaction durations in each class, mean, median and checkpoint share; never call checkpoint-labelled duration an isolated checkpoint phase.

Independent verify.py recomputes counts, counter classification, all sums/medians/shares, exact historical Git source hashes and SQLite settings. check-audit.py accepts actual files and rejects a changed checkpoint flag,missing sample and altered summary share in owned temporary copies. No observations are removed, no A/A observer calibration or causal Lin-vs-SQLite speedup is claimed. macOS results do not predict Linux performance. Stage-level sync/serialization attribution remains unmeasured.
