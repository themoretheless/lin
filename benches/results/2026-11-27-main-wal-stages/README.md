представления значений в записанных парах (индекс, значение). Входные
параметры: insert_rows как в таблице, samples=1, timestamp_ms=123456.

проверить кодирование коротким словарём за один проход без изменения
генерации векторов. Выигрыш по времени требует отдельного парного замера.

### Границы парного замера встроенных движков

В прогоне 46048912069 каждая пара стартует в отдельных процессах. Порядок движков чередуется. Для DuckDB «первый» означает первую вставку в процессе, «повторные» — ещё четыре вставки в том же процессе. Для каждой вставки оба движка создают новую пустую базу. Рост уже заполненной таблицы этот опыт не измеряет.

Lin заранее разбирает запрос с литералами и запускает подготовленный INSERT под таймером. На 100k он выполняет десять подготовленных выражений в одной транзакции. У SQLite заранее подготовлен параметризованный INSERT, привязка значений входит в замер. У DuckDB строки заранее сформированы, а открытие Appender, передача значений, flush и commit входят в замер. Сравнение показывает время этих конкретных API после подготовки данных. Для сквозного времени загрузки потребуется включить подготовку литералов и разбор запроса Lin.

Оба клиента проверяют шесть сохранённых полей. Lin дополнительно формирует штатные эмбеддинги. Для SQLite WAL/FULL проверяется чтение после повторного открытия, для Lin — восстановление из копии файлов до закрытия исходной базы.
