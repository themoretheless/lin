# Production-source full-sync mutation baseline

This measures a previously unqualified scope, not an optimization candidate. Source baseline is the Rust content of production04749994b9ca7a090476b95401f0f7166d8b870a, with the separately saved benchmark-only durable extension from14a7a58d. Existing native/read benchmarks and production API remain unchanged. No Row newtype is introduced. This experiment runs independently of the frozen COW source qualification and cannot qualify that candidate.

24 cases = UPDATE/DELETE/explicit commit/explicit rollback ×1k/10k rows ×Lin Full /SQLite FULL DELETE /SQLite FULL WAL. Both SQLite modes remain visible regardless of wins. See ../2026-10-27-durable-mutation-coverage/protocol.md for fixture/oracle/timing contracts. All columns, generated Lin hash/embedding and total rows are checked after clean close/reopen on fresh validation fixtures before calibration and after measurement. Clean reopen is not a crash test. Positive local24 and negative fault24 controls are saved in the coverage archive; CI reruns positive24 on Linux before timing.

Two six-round series; each of24 cases runs in an isolated process for each of two rotated labels baseline/control. These labels use the same executable:576 processes, eight measured observations each=4608. No warmup, max iterations1; same fresh fixture and lifecycle for every observation. Case order rotates by round; labels rotate per case. No allocator changes or preload. GNU time captures process peak RSS; it includes fixture/oracle/reopen and is not isolated operation memory. Wrapper PID is GNU time's PID, not the benchmark PID. Binary/source/build input hashes, environment, loads, elapsed times, exits, observations and all losses are retained.

Per-process latency is median of eight observations. Each Lin-vs-SQLite comparison pairs the same round and label; report each journal mode, size, operation, label and six-round series separately. Median Lin/SQLite <1 is a numeric Lin win. A/A is median absolute 100*(1-control/baseline) per case per series. These descriptive comparisons are not a source-candidate acceptance gate. Report384 numeric comparisons without dropping unfavourable results. Oracle checks run on fresh pre/post fixtures, not on every timed iteration.

The independent verifier recomputes medians, ratios, win counts, A/A and RSS from all raw coordinates. Protocol tests generate a full synthetic matrix then corrupt RSS and peer win counts; both must be rejected. Synthetic results are never benchmark evidence. full_objective_achieved and source_candidate_qualified remain false even if Lin wins every pair: other scenarios, optimization acceptance and seven other named peers are outside this experiment. Durability configurations and acknowledged work remain explicit; rollback is not a committed persistent update.
