# Draft column batch benchmark protocol — not yet timed

Two target workloads insert 1k/2k documents in one Full transaction, through the same prepared 500-row programs in both runtime versions. These sizes are supported by the unmodified baseline. The new 10k capacity is verified separately and is not misrepresented as a successful baseline performance comparison. Runtime baseline is corrected COW 625bc7180; candidate changes only compatible column Batch dispatch and retains fdatasync.

Setup creates a fresh durable Lin store and the same docs index. It prepares programs and constructs an independent in-memory reference with the same schema and one transaction, retaining only normalized JSON values for the oracle. The measured region begins with transaction creation, executes the prepared programs, includes temporary output drops, and commits. Close/reopen and complete row/value comparison occur outside timing. SQLite WAL FULL equivalents use a single transaction and cached prepared INSERT, the same row fixtures and original six-column schema. Lin keeps its default embedding/FTS features; this is the declared native API contract, not equal physical schemas or equal driver calls.

Twenty existing cases from the fsync component matrix become controls, unchanged: six Lin durable single-row writes, scalar Full, six SQLite WAL writes, scalar Normal, two native UPDATE, two INSERT, native rollback and FTS selective. Add the two new Lin targets and two new SQLite controls: 24 cases. Two six-pair series, rotated baseline/control/candidate order, eight observations, one operation per observation, zero warmup: 864 fresh processes / 6912 observations. Control role reuses the exact baseline executable. All 48 functional smokes must pass first. Before timing also require 460 release tests / 2 ignored, compiled missing-child negative, all 32 grouped-history value probes and successful real 04749994 reader checks.

Targets require all six pair gains positive and median gain above median absolute A/A; controls require gain >= -max(2 percent, absolute A/A). Any failed window rejects this component. Retain all original raw results; no unchanged retry, waiver, production adoption or complete eight-peer claim. A separate whole-engine/peer refresh remains required even if this draft component later passes. Local builds and smokes alone do not qualify performance. Freeze source, harness, matrix and analyzer before Linux timing.
