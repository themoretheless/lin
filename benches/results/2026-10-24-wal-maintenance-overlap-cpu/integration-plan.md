# Transaction prototype constraints

1. Split typed column encoding into a pure, bounded result containing exact legacy codec identity and payload bytes; keep existing msgpack/edge/mismatch fallback and error order. Prove byte equivalence on real/special-value/empty/mixed-column cases before parallel integration. No file writes in the worker.
2. Start work only after row defaults, identity checks and embedding are complete. Worker borrows immutable finalized rows/columns; caller maintains indexes/FTS/maps. Join on every success/error path. Unique/index error precedence stays original; failed encoding or index work must leave the original rollback behavior. Inject worker-creation failure and preserve serial fallback. Initial eligibility may be a single durable insert; multi-statement/explicit transactions retain serial behavior unless staged metadata and batch semantics are separately proved.
3. Carry owned staged bytes explicitly through transaction output, rather than a hidden global or unvalidated reusable pending buffer. Record/check generation and next-id metadata where required. Discard on every failure/retry. Keep generic serialization/replay contracts and codec IDs unchanged. Avoid storing stale speculative bytes for later commits.
4. Only the caller writes after original quota/index/transaction checks, then performs original Full sync before acknowledgement. Preserve logical quota accounting, checksum/envelope bytes and log rollback/truncation behavior. Recycle buffers with explicit ownership where possible; measure cold allocation, repeated commits and peak RSS before choosing a default policy.
5. Validate exact legacy frames, complete independent query-ID/value sets and f32 bits, unique/partial/index/FK/quota failures, thread-failure fallback, empty/noneligible cases, multi-statement fallback and process-exit acknowledged replay. Run full workspace. Then two native/durable engine series with unchanged SQLite controls plus A/A calibration; refresh available peers only after candidate qualifies. Keep MSSQL/Kusto live gates and the durable SQLite gap explicit.

This is a design boundary for the next measured prototype, not an implemented transaction path or an accepted optimization.
