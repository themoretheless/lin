# Caller-allocated embedding outputs: candidate, not accepted

Based on b9f10bc776b05eb5235237e9a900c2ef6aaed1fd. Only src/embed.rs changes. Prior Linux diagnostic 41636139554 attributed 2.59–3.80 microseconds/row to Arc allocation+copy versus 0.09–0.10 normalization and 0.06 cleanup. That does not separate allocator/page-fault/copy/scheduling cost. This candidate tests allocation ownership, not different embedding arithmetic.

Existing threshold 512, thread count/chunk boundaries and serial fallback remain. Before spawning, caller allocates one uninitialized Arc slice per text. Worker threads exclusively initialize all slots from the same normalized scratch vector, including exact positive-zero slots, and clear touched scratch state. Caller converts to initialized Arc only after every worker joined successfully. Unwinding drops uninitialized Arc slices without interpreting f32 contents. No raw aliasing, shared uninitialized references or custom allocator. Allocation is inside the operation timer; row validation and all embedding readback remain mandatory. Public Row/Cell/Embedder contract, model/hash/dimension/feature order, FTS and sync unchanged.

This differs from rejected fused sparse-output implementations: output allocation occurs entirely on the caller, and normalization still follows the original sparse/dense rules before a full dense copy. It differs from persistent worker/arena experiments: no persistent threads or buffers, output slab representation, owned text queues or cross-call cache. Allocation still costs one Arc per row and one temporary output-pointer Vec; moving it to the caller might serialize the bottleneck or increase memory pressure. No performance gain is claimed until a new complete end-to-end gate passes.
