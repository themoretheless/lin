# Prepared INSERT key-layout cache — candidate

Different from the rejected runtime batch tweaks, worker pools and modulo specialization. Public Row remains BTreeMap, default embeddings/FTS/sync remain unchanged. Prepared now optionally owns an Arc-shared immutable key-layout descriptor for a single INSERT with at least128 records, at most32 fields and at most4096 key bytes in the first record. Every record's complete ordered field-name sequence, including duplicates, is verified at prepare time. A template of Null cells and last-occurrence source slots is cached; no literal values, timestamps, IDs or store state are cached.

Runtime uses this verified layout to clone the row template and evaluate each record's values with that run's timestamp. It avoids rebuilding the template/slot search in each morsel and repeated per-row key comparisons. The private immutable Prepared AST keeps the descriptor valid. Mixed field orders/shapes, wide/large keys, small batches and multi-statement programs use the original runtime builder. No additional user-facing error or raised quota is introduced. Single prepared statements inside an interactive transaction receive the same descriptor.

Tradeoffs: extra bounded prepared metadata and one field-layout verification pass during preparation. This moves static checks into planning, so complete worker lifecycle, preparation cost, mixed-layout behavior and RSS need qualification alongside prepared execution. A faster operation timer alone does not prove a cold application gain.

13 focused record tests pass: exact independent record_row equivalence, last duplicate wins, runtime now values across two clocks, short tail morsels, reordered/oversized keys and wide fallback, Arc-sharing across Prepared clones, execution into two databases with default vectors, and multi-statement fallback. Full default workspace:417 passed, zero failed, three ignored. Ordinary default release worker built; exact binary/source/compiler hashes are retained in build-status.json.
