# Execution-local shared row shape — unqualified prototype

Based on b9f10bc776b05eb5235237e9a900c2ef6aaed1fd runtime. Only src/exec.rs changes. The complete field sequence is checked once inside insert_bulk before starting workers. At least 512 records, 1..32 fields and at most 4096 first-record key bytes are required. The descriptor borrows exactly the checked record slice; workers receive ranges into that slice. Last duplicate field wins and values/now remain execution-time work. No persistent Prepared metadata, API/Row change, feature removal or sync change.

Hypothesis: caller-owned common template and one verification pass can reduce redundant worker setup and alter allocation locality without moving work outside the operation timer. Same-host diagnostics of the rejected prepare-cache variant motivated this experiment but do not establish this mechanism or qualify this new source. Existing fallback remains for all ineligible layouts. A mismatched/oversized input takes the previous per-chunk implementation.
